## Problem & Context

`0114` can retrieve reviewed query exemplars and `0115` can resolve their
tables, columns, meanings, access classes, and drift status. SFMeridian still
cannot safely answer a desk question from those assets. It has no interface
that makes verification mandatory before execution, no read-only execution
seam, and no `0080` `Reader` that turns reviewed metric-source queries into
governed `0008` facts. A model or caller could therefore invent an identifier,
omit the point-in-time predicate, interpolate user input, or bypass the
governed tier and still reach a database (`0113` K-001, K-003, K-007).

This phase supplies the first end-to-end, shadow-mode `ask` path. Every
question goes to `0080` first. Questions within the governed vocabulary are
answered there from reviewed metric-source queries; governed ambiguity is
returned as a clarification. Only questions outside the governed vocabulary
may reach retrieval-first SQL composition. Every query is verified
deterministically, execution requires a token bound to the exact verified
query and parameters, and every result carries replayable provenance.

## Goals

- Answer governed metric questions through `0080` and a plugin `Reader`, with
  no SQL-composition fall-through on governed answers or clarifications.
- Compose the non-governed tail retrieval-first (`reuse` → `adapt` →
  `generate`) and disclose the path and source exemplars.
- Make unsafe SQL unexecutable by interface: deterministic verification issues
  a short-lived token for one exact query, parameter set, profile, catalog
  snapshot, configuration, and policy.
- Execute only read-only, bounded queries through injected connections and
  return redacted rows with complete `0070`-compatible provenance and replay.
- Provide an executable synthetic SQLite fixture matching the `0115` catalog,
  plus static dialect coverage for PostgreSQL, Oracle, and Databricks SQL.
- Add the `sql_composer` and `sfmeridian_orchestrator` loop agents (coverage
  rows C-03 and C-04) without duplicating specialist agents' workflows.
- Refuse write-back at runtime and carry bounded, redacted evidence in
  specialist handoff payloads.

## Non-Goals

- No final claim-level grounding, recomputation gate, abstention policy, or
  release-quality golden-question evaluation; `0117` owns those controls.
- No Python API, MCP server, Claude Code plugin, contract JSON Schema files, or
  `1.0.0` release; `0118` owns packaging and app surfaces.
- No analytics, optimization, risk, portfolio-management, or model judgement;
  the plugin hands evidence to the existing agents named by `0113` R-021.
- No promotion of generated SQL into the query repository and no modification
  of reviewed exemplars, semantic bindings, packs, or catalog snapshots.
- No database credentials or bundled drivers. Connections, the verification
  signing key, clocks, model completion, and optional `EXPLAIN` runner are
  injected by the host.
- No SQL Server or Snowflake execution. They remain deferred by `0113`.
- No insight publication, even when configuration requests it. This phase
  always refuses write-back; eligibility can only be revisited after reviewed
  packs and the later approval flow exist.

## Non-Functional Requirements

| ID | Requirement | Target |
| --- | --- | --- |
| NFR-001 | Determinism | Frozen config, catalog, index, fixture, clock, signing key, and model response reproduce composition records, verifier decisions, redacted results, run IDs, and envelope hashes. |
| NFR-002 | Safety | Zero write, DDL, multi-statement, unbounded, unverified, expired-token, or identifier-fabricating query reaches a connection; the adversarial rejection rate is 100%. |
| NFR-003 | Portability | Python 3.11+ standard library in the core; only `sfmeridian.governed` imports the pinned `quantsmith` interfaces; connections and drivers are injected. |
| NFR-004 | Latency and cost | Plugin overhead p95 is at most 15 seconds excluding database execution; limits, timeouts, maximum repairs, and optional `EXPLAIN` cost are configurable and recorded. |
| NFR-005 | Data safety | Fixtures are synthetic and disclosed; credentials, signing material, raw sensitive parameters, and withheld values never enter rows, errors, traces, handoffs, or envelopes. |
| NFR-006 | Catalog consistency | The targeted spec gate passes under `QF_STAGE_ENFORCE=1`; implementation may not be marked complete until the full suite and all repository gates pass with no new findings. |

## Risks

| ID | Risk | Impact | Mitigation |
| --- | --- | --- | --- |
| RISK-001 | The tokenizer accepts syntax it does not fully understand. | Unsafe or fabricated SQL executes. | Fail closed on unsupported constructs; adversarial suite; optional stricter parser remains gated by an admission review. |
| RISK-002 | A valid token is replayed against different context or after drift. | Previously safe SQL runs under stale policy or schema. | Token binds snapshot, config, policy, clearance, parameters, and expiry; replay re-verifies and compares fixture/snapshot hashes. |
| RISK-003 | Governed ambiguity falls through to a convenient exemplar. | Wrong metric or viewpoint is answered confidently. | Typed route outcome; clarification is terminal; AC-009. |
| RISK-004 | A reviewed query is safe structurally but stale semantically. | Wrong numbers with good provenance. | Only primary, undrifted sources; current catalog and mapping; `0117` adds the release grounding/evaluation gate. |
| RISK-005 | Driver or `EXPLAIN` output leaks credentials or warehouse details. | Confidential data enters traces. | Injected adapters return normalized fields; exceptions scrubbed; raw plans are not persisted. |
| RISK-006 | The orchestrator absorbs specialist judgement. | Duplicated and weakly governed workflows. | Bounded handoff payloads; receiver and never-boundary validated against `handoffs.json`; no receiver changes. |
| RISK-007 | Shadow-mode tail results are mistaken for release-qualified answers. | Users over-trust an ungrounded draft. | Every tail result is labelled shadow mode; `0117` grounding and golden gate remain required before release. |

## Assumptions & Open Questions

- Assumption: the host can inject a query-only connection, monotonic clock,
  and token-signing material without placing them in configuration.
- Assumption: PostgreSQL executes in CI when its service exists; Oracle and
  Databricks are verified statically until adopter-side nonproduction runners
  exist.
- Open (not blocking): the `0081` `securities_financing_prime` pack and six
  staged amendments await the named reviewer's decision. Until then governed
  answers carry the unreviewed-pack caveat and write-back remains refused.
- Open (not blocking): admission review for optional database drivers. Until
  completed, hosts inject drivers and no driver extra ships.
